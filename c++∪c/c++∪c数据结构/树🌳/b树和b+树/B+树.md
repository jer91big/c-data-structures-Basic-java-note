## 🎬 第一幕：树的世界设定

想象一棵树，不是普通的树，而是一棵“数据库之树”。

🌳 它有几个奇怪的规则：

- 每个节点（树枝）可以装 **多个数据**
- 所有“真正的数据”都只存在在 **最底层（叶子节点）**
- 上层节点只负责：👉 **导航（像路标）**

---

## 🎬 第二幕：角色登场

我们把节点分成两类：

### 🧠 内部节点（导航员）

像这样：

```
[10 | 20 | 30]
```

它的作用不是存数据，而是说：

> 小于10往左走  
> 10~20之间走第二条路  
> 20~30走第三条路  
> 大于30往最右

👉 就像高速公路分叉口的指示牌

---

### 📦 叶子节点（仓库）

真正存数据：

```
[1, 5, 8] → [10, 15] → [20, 25, 28] → [30, 35]
```

注意重点：  
👉 **叶子节点之间是连起来的（像链表）！**

这点非常关键！！

---

## 🎬 第三幕：查找（动画过程）

假设你要找：`25`

🎥 镜头开始：

1️⃣ 从根节点开始

```
[10 | 20 | 30]
```

👉 25 在 20~30之间  
👉 往第三个孩子走

---

2️⃣ 到达叶子节点：

```
[20, 25, 28]
```

👉 找到了 ✔

---

💡 关键感受：

👉 **上层像地图导航**  
👉 **底层才是真正的数据**

---

## 🎬 第四幕：插入（最精彩的剧情）

假设现在插入：`26`

---

### 🟢 Step1：找到位置

走流程：

```
[10 | 20 | 30] → [20, 25, 28]
```

插入后：

```
[20, 25, 26, 28]
```

---

### 🔴 Step2：爆了！（节点满了）

假设一个节点最多只能放3个数

现在有4个 → ❌ 超了

---

### ✂️ Step3：分裂（关键操作）

拆成两个节点：

```
[20, 25]    [26, 28]
```

---

### ⬆️ Step4：向上汇报

把“分界值”`26`告诉爸爸节点

原来：

```
[10 | 20 | 30]
```

变成：

```
[10 | 20 | 26 | 30]
```

---

💥 如果爸爸也满了？

👉 继续往上裂！

👉 一直裂到根节点，甚至可能长高一层！

---

## 🎬 第五幕：为什么一定要叶子链表？

看这个操作：

👉 查找区间：`20 ~ 30`

如果是普通树：  
👉 你要到处跳

但在B+树：

```
[20, 25] → [26, 28] → [30, 35]
```

👉 顺着链表一路扫！

💡 这就是数据库最爱它的原因：

👉 **范围查询极快**

---

## 🎬 第六幕：总结一下本质（你必须抓住的点）

别记代码，先记这3条：

### ① 数据只在叶子

👉 上层只是“索引”

---

### ② 叶子节点是链表

👉 支持范围查询

---

### ③ 插入会“分裂 + 向上冒泡”

👉 类似“气泡往上顶”

---

## 🎬 最后一幕：一句人话总结

👉 B+树就是：

> “上层做导航，底层存数据，叶子全连起来的一棵多叉平衡树”

---

如果你后面要写代码或考试：

1. 为什么数据只在叶子？
2. 为什么叶子要连起来？
3. 分裂时到底“往上推什么”？
