# 📚 Maven 依赖范围 (Dependency Scope) 笔记

在 Maven 中，`scope` 标签用来控制依赖的**作用范围**。它决定了引入的 Jar 包在什么阶段（编译、测试、运行）才可用，以及是否会被打包进最终的项目中。

## 一、 Maven 的三种 classpath（类路径）

在理解依赖范围之前，先明确 Maven 有三套 classpath：

1. **编译范围（Compile classpath）**：执行 `mvn compile` 时使用。
    
2. **测试范围（Test classpath）**：执行 `mvn test` 时使用。
    
3. **运行/打包范围（Runtime classpath）**：项目实际运行或打包时使用。
    

## 二、 核心依赖范围详解

Maven 一共提供了 **6 种** 依赖范围，最常用的是前四种：

|**依赖范围 (<scope>)**|**编译阶段**|**测试阶段**|**运行阶段**|**是否参与打包**|**典型应用场景 / 例子**|
|---|---|---|---|---|---|
|**`compile`**<br><br>  <br><br>_(默认)_|**有效**|**有效**|**有效**|**会打包**|大多数通用第三方库（如 `fastjson`, `commons-lang3`）|
|**`test`**|无效|**有效**|无效|**不打包**|仅用于测试的框架（如 **`junit`**）|
|**`provided`**|**有效**|**有效**|无效<br><br>  <br><br>_(由容器提供)_|**不打包**|编译测试需要，但运行环境已自带的库（如 **`servlet-api`**）|
|**`runtime`**|无效|**有效**|**有效**|**会打包**|编译时不需要、运行时才加载的实现类（如 **`MySQL 驱动`**）|
|**`system`**|**有效**|**有效**|无效|**不打包**|需指定本地系统的绝对路径 Jar（**极不推荐**使用）|
|**`import`**|—|—|—|—|仅用于 `<dependencyManagement>` 中，解决多模块继承问题（高级特性）|

## 三、 💡 重点难点解析与记忆技巧

1. **为什么 JUnit 的 scope 是 `test`？**
    
    - 因为我们在写业务代码（生产环境）时不需要用到测试工具，如果把它打包到线上服务器，不仅浪费空间，还可能带来安全隐患。
        
2. **为什么 Servlet-api 的 scope 是 `provided`？**
    
    - 因为当你把项目部署到 **Tomcat** 服务器上时，Tomcat 本身就已经内置了 Servlet 的相关 API。如果在打包时把它们也打进项目中，运行时就会和 Tomcat 自带的发生类冲突。
        
3. **为什么 MySQL 驱动通常是 `runtime`？**
    
    - 因为你在写 Java 代码操作数据库时，写得全都是 JDBC 的**标准接口**（java.sql.*），编译时根本不依赖具体的 MySQL 驱动实现类；只有当程序跑起来、真正去连接数据库时，才需要驱动去建立连接。
