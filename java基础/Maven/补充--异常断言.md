## 一、先理解它是干什么的

假设你写了一个除法方法：

```
public int divide(int a, int b) {
    return a / b;
}
```

如果调用：

```
divide(10, 0);
```

Java 会抛出 `ArithmeticException` 异常，因为整数不能除以 0。

现在我们想写一个测试，验证这个方法在除以 0 时，确实会抛出异常，而不是正常运行。

这时候就可以使用 `assertThrows()`。

## 二、括号里的两个参数是什么意思？

```
assertThrows(ExpectedException.class, Executable);
```

### 第一个参数：`ExpectedException.class`

告诉测试框架：我预期会出现什么异常。

例如：

```
ArithmeticException.class
```

意思是：我预期代码会抛出 `ArithmeticException` 异常。

注意，`.class` 在这里表示获取这个类对应的 `Class` 对象，不是创建异常对象。

### 第二个参数：`Executable`

告诉测试框架：具体执行哪段代码。

通常我们会传入一个 Lambda 表达式：

```
() -> divide(10, 0)
```

你可以暂时把它理解成：先把要执行的代码交给测试框架，由测试框架来运行它。

## 三、完整代码应该怎么写？

假设你使用的是 JUnit 5。

```
import org.junit.jupiter.api.Test;

import static org.junit.jupiter.api.Assertions.assertThrows;

public class CalculatorTest {

    public int divide(int a, int b) {
        return a / b;
    }

    @Test
    public void testDivide() {
        assertThrows(
            ArithmeticException.class,
            () -> divide(10, 0)
        );
    }
}
```

我们模拟一下运行过程：

第 1 步：执行测试

JUnit 运行 `assertThrows()`。

第 2 步：运行 Lambda 代码

```
() -> divide(10, 0)
```

执行整数除以 0，触发异常。

第 3 步：检查异常类型

实际异常与预期类型匹配，测试通过。

如果代码没有抛出异常，测试反而会失败。因为你明明说了“我预期它会出错”，结果它却正常执行了。

## 四、为什么第二个参数要写 `() -> ...`？

你可能会想，为什么不直接写：

```
assertThrows(ArithmeticException.class, divide(10, 0));
```

因为 `divide(10, 0)` 会立即执行，而且它的返回值类型是 `int`，并不是 `assertThrows()` 所需要的 `Executable`。

而：

```
() -> divide(10, 0)
```

是一个 Lambda 表达式，它把待执行的操作交给测试框架。

你可以暂时记住这个规律：

- `ArithmeticException.class`：检查什么异常。
    
- `() -> divide(10, 0)`：执行哪段代码。
