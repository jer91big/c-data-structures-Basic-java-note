
# 📚 JUnit 单元测试与断言笔记

## 一、 Maven 中的 JUnit 依赖配置

在 Maven 项目的 `pom.xml` 中，我们通常使用 **JUnit 5**（目前主流版本）。需要在 `<dependencies>` 标签中引入测试依赖：

  

XML

```
<!-- JUnit 5 依赖 -->
<dependency>
    <groupId>org.junit.jupiter</groupId>
    <artifactId>junit-jupiter</artifactId>
    <version>5.10.0</version> <!-- 版本号可根据实际情况调整 -->
    <scope>test</scope>
</dependency>
```

_💡 提示：`scope` 为 `test` 表示该依赖只在测试阶段生效，不会被打包进最终的生产环境程序中。_

  

## 二、 JUnit 核心注解 (Annotations)

注解用来控制测试方法的执行顺序和生命周期。

  

|**注解**|**说明**|**执行时机**|
|---|---|---|
|**`@Test`**|标记一个方法为**测试方法**。只有加了它，Maven 在测试时才会执行该方法。|每次运行测试方法时|
|**`@BeforeEach`**|在**每个**测试方法执行**之前**运行。|每个 `@Test` 运行前|
|**`@AfterEach`**|在**每个**测试方法执行**之后**运行。|每个 `@Test` 运行后|
|**`@BeforeAll`**|在**所有**测试方法执行**之前**运行（方法必须是 `static`）。|整个测试类运行前（仅一次）|
|**`@AfterAll`**|在**所有**测试方法执行**之后**运行（方法必须是 `static`）。|整个测试类运行后（仅一次）|
|**`@Disabled`**|临时**禁用**某个测试方法（跳过不执行）。|忽略该测试|

### 📝 代码示例：

Java

```
import org.junit.jupiter.api.*;

public class CalculatorTest {

    @BeforeAll
    static void initAll() {
        System.out.println("--- 整个测试开始：初始化资源 ---");
    }

    @BeforeEach
    void setUp() {
        System.out.println("准备测试数据...");
    }

    @Test
    void testAdd() {
        int result = 1 + 1;
        Assertions.assertEquals(2, result); // 断言
        System.out.println("执行加法测试");
    }

    @AfterEach
    void tearDown() {
        System.out.println("清理测试数据...\n");
    }

    @AfterAll
    static void tearDownAll() {
        System.out.println("--- 整个测试结束：释放资源 ---");
    }
}
```

## 三、 JUnit 5 断言 (Assertions)

断言（Assertion）是单元测试的核心，用来判断“实际结果”是否符合“预期结果”。如果不符合，测试就会报错（AssertionFailedError）。

  

> **注意**：JUnit 5 的断言方法通常都包含在 `org.junit.jupiter.api.Assertions` 类中。为了代码简洁，通常会静态导入：
> 
> `import static org.junit.jupiter.api.Assertions.*;`
> 
>   

### 1. 相等与不等断言

- **`assertEquals(expected, actual)`**
    
      
    - 检查预期值与实际值是否相等（底层基于 `equals`）。
        
          
        
- **`assertNotEquals(unexpected, actual)`**
    
      
    - 检查实际值是否不等于某个值。
        
          
        

Java

```
assertEquals(10, calculator.add(5, 5));
assertNotEquals(5, calculator.add(2, 2));
```

### 2. 布尔断言 (True / False)

- **`assertTrue(condition)`**
    
      
    - 检查条件是否为 `true`。
        
          
        
- **`assertFalse(condition)`**
    
      
    - 检查条件是否为 `false`。
        
          
        

Java

```
boolean isEven = (4 % 2 == 0);
assertTrue(isEven);
assertFalse(5 > 10);
```

### 3. 空值断言 (Null)

- **`assertNull(actual)`**
    
      
    - 检查对象是否为 `null`。
        
          
        
- **`assertNotNull(actual)`**
    
      
    - 检查对象是否**不为** `null`。
        
          
        

Java

```
String str = null;
assertNull(str);

String name = "Java";
assertNotNull(name);
```

### 4. 引用与相同断言

- **`assertSame(expected, actual)`**
    
      
    - 检查两个引用是否指向**同一个内存地址**（即 `==` 比较）。
        
          
        
- **`assertNotSame(unexpected, actual)`**
    
      
    - 检查两个引用是否不是同一个对象。
        
          
        

Java

```
String s1 = "hello";
String s2 = "hello";
assertSame(s1, s2); // 字符串常量池，地址相同
```

### 5. 异常断言 (Exception)
[[异常的几种写法]]//补充异常的写法
测试某段代码是否**按预期抛出了异常**（比如传入错误参数时抛出 `IllegalArgumentException`）。

  

- **`assertThrows(ExpectedException.class, Executable)`**
    
      
    

Java

```
@Test
void testException() {
    // 验证当除数为 0 时，是否抛出了 ArithmeticException 异常
    assertThrows(ArithmeticException.class, () -> {
        int result = 10 / 0; 
    });
}
```

### 6. 超时断言 (Timeout)

测试某段代码是否在规定的时间内执行完成。

  

- **`assertTimeout(duration, Executable)`**
    
      
    

Java

```
@Test
void testPerformance() {
    // 验证代码块是否能在 1 秒内执行完
    assertTimeout(java.time.Duration.ofSeconds(1), () -> {
        Thread.sleep(500); // 模拟耗时操作
    });
}
```

## 四、 💡 断言失败时的自定义提示信息

几乎所有的断言方法，都支持在参数的**最后面**追加一个字符串参数，用来在断言失败时输出自定义的错误描述：

Java

```
int actualAge = 15;
// 如果断言失败，控制台会打印 "学生的年龄计算不正确"
assertEquals(18, actualAge, "学生的年龄计算不正确"); 
```
