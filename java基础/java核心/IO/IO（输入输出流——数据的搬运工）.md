

📽**动画场景引入** 欢迎回到“Java内存城”！ 你的程序现在不仅能在城里（内存）自娱自乐，他还想和城外的大世界（比如硬盘里的文件、网络上的其他电脑）做生意。 但是，城墙太高，数据怎么进出呢？包工头 JVM 雇佣了两大帮派的“搬运工（Stream 流）”，并在城墙上架起了传送带（管道）。

- **输入（Input）**：把城外的东西搬进城里（比如读取硬盘上的文件）。
    
- **输出（Output）**：把城里的东西运到城外（比如把数据写成一个文本文件）。
    

这两大帮派分工明确： **第一大帮派叫“字节流（Byte Stream）”**：他们是一群蒙眼大汉，力大无穷。他们不管搬的是什么，MP4电影、MP3音乐、还是苍老师的照片，他们只认底层的 0 和 1（字节）。原封不动地搬，绝不瞎看。 **第二大帮派叫“字符流（Character Stream）”**：他们是一群戴着老花镜的文化人。他们**只搬纯文字**（比如 txt 文件、代码文件）。在搬运的过程中，他们还会掏出字典（字符编码表，比如 UTF-8），把底层的 0 和 1 翻译成你能看懂的汉字！

📖**核心概念** IO，全称 Input/Output，即输入输出。

- **到底是什么**：它是 Java 程序用来和外部设备（文件、网络、控制台）交换数据的一套管道系统。
    
- **解决什么问题**：解决了程序运行结束后数据丢失的问题（把数据持久化保存到硬盘），以及从外部获取资源的问题。
    

🧠**底层原理：抽水机的流水线** 无论是字节流还是字符流，它们在底层的运作机制就像是**水管和抽水机**。

1. **接水管**：当你想读一个文件，就是在文件和内存之间接了一根水管（打开流）。
    
2. **抽水**：数据就像水一样，一滴一滴（一个一个字节）或者一桶一桶（用数组当缓冲桶）地被抽过来。这是一个**顺序的单向操作**，水流过去了就回不来了。
    
3. **拔水管（重点！）**：水抽完了，你**必须手动把水龙头关掉，把水管拔下来（调用 `close()` 方法）**。如果不关，这根水管就一直霸占着那个文件，别人想删都删不掉（文件被占用），久而久之，操作系统的水管被接光了，程序就会崩溃瘫痪！
    

💻**基础语法&常用API** 来看看怎么指挥这群搬运工（注意看我是怎么优雅地“拔水管”的）：

Java

```
import java.io.*;

public class IOTheater {
    public static void main(String[] args) {
        
        // 🚨 重点语法：try-with-resources（自动拔水管机）
        // 把水管写在 try 的小括号 () 里，Java 就会在用完后自动帮你关掉水管，再也不怕忘写 close() 啦！
        
        // 场景 1：用【字符流】读一首诗 (只能读纯文本)
        try (FileReader fr = new FileReader("D:\\poem.txt");
             // 给老花镜大爷配一辆小推车（Buffer缓冲流），不用每次只搬一个字，搬满一车再拉过来，速度飞升！
             BufferedReader br = new BufferedReader(fr)) {
            
            String line;
            while ((line = br.readLine()) != null) { // 每次读一整行
                System.out.println("大爷读到：" + line);
            }
            
        } catch (IOException e) {
            System.out.println("文件没找到或者读出错了！");
        }

        // --------------------------------------------------

        // 场景 2：用【字节流】复制一张照片 (万能搬运工)
        try (FileInputStream fis = new FileInputStream("D:\\dog.jpg"); // 抽水管
             FileOutputStream fos = new FileOutputStream("D:\\dog_copy.jpg")) { // 排水管
            
            // 准备一个能装1024滴水的“水桶”
            byte[] bucket = new byte[1024]; 
            int len; 
            
            // 只要没抽干，就一直抽进水桶里
            while ((len = fis.read(bucket)) != -1) { 
                // 把水桶里的水，倒进排水管里
                fos.write(bucket, 0, len); 
            }
            System.out.println("照片复制完成！");
            
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}
```

⚠️**高频坑&易错点**

1. **用蒙眼大汉（字节流）去搬中文字符**
    
    - **坑在哪里**：你用 `FileInputStream`（字节流）去读一篇中文小说，然后在控制台打印出来，结果发现全是 `???` 和乱码。
        
    - **为什么错**：中文字符在 UTF-8 编码里通常占 3 个字节。蒙眼大汉每次只搬 1 个字节，他直接把一个汉字“大卸三块”搬过来了。你拿到这 1/3 个汉字去显示，系统根本认不出来，只能给你展示乱码。
        
    - **正确姿势**：读写纯文本，**坚决使用戴老花镜的文化人——字符流（FileReader/Writer）**。
        
2. **忘记写 `close()`，水管漏水了！**
    
    - **坑在哪里**：很多老代码或者新手写的代码，没有用上面讲的 `try-with-resources` 语法，而是直接 `new` 了流，最后忘记写 `close()`。
        
    - **为什么错**：会导致内存泄漏（水管一直占着内存），并且在 Windows 系统下，你会发现你想删除那个文件时，系统提示：“操作无法完成，因为文件已在 Java(TM) Platform 中打开”。
        
    - **正确姿势**：永远把流的创建写在 `try()` 的括号里，让 Java 帮你自动关水龙头。
        

✅**课堂小结**

- **方向**：以内存为中心，外到内是 **Input**，内到外是 **Output**。
    
- **分类**：
    
    - **字节流（InputStream/OutputStream）**：万能搬运工，适合搬图片、视频、音频。
        
    - **字符流（Reader/Writer）**：文化人，自带翻译字典，专治中文文本乱码。
        
- **提速神器**：只要加上 **Buffered（缓冲流）**，就能从小手推车升级为大卡车，速度成百上千倍提升！
    
- **铁律**：用完流**必须关闭**（强烈推荐 `try-with-resources`）。
