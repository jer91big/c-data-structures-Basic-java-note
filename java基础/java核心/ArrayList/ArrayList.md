# 🎬 第三课：单列集合之王 —— `ArrayList` 底层黑魔法

在面向对象阶段，如果我们想存一堆对象，只能用数组（`Hero[] heroes = new Hero[5];`）。

但数组有个极其恶心的缺点：**长度固定，一旦开辟就不能变**。要放第 6 个元素？对不起，装不下了！

于是，**`ArrayList`（动态数组）** 应运而生。它的特点是：**表面上看是一个无限扩容的列表，底层其实依然是数组**。

## 🛠️ 1. `ArrayList` 的基础使用

先温习一下基本操作，体会它的方便：

Java

```
// 使用泛型 <String> 限定里面只能装字符串
ArrayList<String> list = new ArrayList<>();

// 1. 添加元素
list.add("亚瑟");
list.add("后羿");
list.add("鲁班七号");

// 2. 根据索引获取元素（索引从 0 开始）
String h = list.get(0); // 亚瑟

// 3. 修改元素
list.set(1, "铠"); // 把索引 1 的后羿改成铠

// 4. 删除元素
list.remove("鲁班七号"); // 或 list.remove(2);

// 5. 获取集合长度
int size = list.size(); // 2
```

## 🚨 深度难点单独讲：`ArrayList` 的无缝自动扩容机制

这是所有面试和底层分析里**必考**的重点！既然底层是固定长度的数组，凭什么 `ArrayList` 可以一直 `add()` 进去无限多的元素？

> **🎬 动画演示（自动扩容全过程）：**
> 
> 1. **空手套白狼（无参构造）**：
>     
>     当你写 `new ArrayList<>()` 时，Java **并没有**立刻在内存里开辟很大空间，而是给了一个**长度为 0 的空数组 `{}`**。
>     
> 2. **第一次 `add()`（惊喜分配）**：
>     
>     当你第一次往里面 `add("亚瑟")` 时，底层检测到数组是空的，轰隆一声，直接开辟了一个**默认初始容量为 10** 的新数组！
>     
> 3. **满员警报（第 11 次 `add()`）**：
>     
>     你一路塞到了第 10 个元素，此时数组已经装得满满当当（`size == capacity == 10`）。
>     
>     当你试图 `add()` 第 11 个元素时，触发了内部的**扩容机制（Grow）**！
>     
> 4. **扩容公式（1.5倍扩容）**：
>     
>     Java 算了一笔账：新的容量 = 原容量 + (原容量 >> 1)，也就是 **新容量 = 原容量 $\times$ 1.5**。
>     
>     现在的容量变成了 **$10 + 5 = 15$**。
>     
> 5. **搬家搬运（数组拷贝）**：
>     
>     Java 在堆内存里开辟了一个全新长度为 **15** 的大数组，然后调用 `System.arraycopy()`，把原来 10 个老元素像搬家一样**原封不动地复制到新数组**里，再把第 11 个元素塞进去。
>     
>     原来的旧数组被扔掉，等待垃圾回收（GC）。
>     

## ⚡ 性能优缺点（读快改慢的秘密）

理解了底层是数组，你就能瞬间秒懂为什么 `ArrayList` 有这样的性能特点：

### 优势：随机访问（查询）极快！🚀

- **为什么？** 因为数组在内存里是一整块连续的空间。你可以直接通过公式 `首地址 + 索引 * 元素大小` **一步算出来**任意位置的内存地址。
    
- 想找第 1000 个元素？`list.get(999)` 的速度和找第 1 个元素一模一样快（时间复杂度 $O(1)$）。
    

### 劣势：中间插入、删除较慢！🐢

- **为什么？** 假设数组里有 100 个元素，你非要在位置 `0`（开头）插入一个新元素。
    
- **动画过程**：为了给开头腾出地方，位置 `0` 到 `999` 的所有元素都必须往后移动一位！搬运数据非常耗费 CPU。
    

## 💡 老师的性能优化小建议

如果你提前知道你的集合大概要装 1000 个数据：

- ❌ **不好**：`List<String> list = new ArrayList<>();`（会导致它从 10 扩容到 15、再扩到 22...一路搬家多次，极其浪费性能）。
    
- 🚀 **极佳**：`List<String> list = new ArrayList<>(1000);`（直接告诉它初始化开辟 1000 的空间，**一次性到位，绝不触发扩容搬家**！）。
