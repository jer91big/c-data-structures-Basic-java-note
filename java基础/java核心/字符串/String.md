# 核心常用 API 篇

## 🎬 第一课：String 的底层“黑魔法”与内存奥秘

在 Java 里，`String` 是我们天天打交道的“老朋友”，但它背后藏着极其傲娇的性格和复杂的内存逻辑。

### 1. 傲娇的性质：为什么 String 变不了？（不可变性）

很多人以为改变一个字符串很容易，比如：

Java

```
String s = "Hello";
s = s + " World"; // 这不就变了吗？
```

**错！它根本没有变！**

> **🎬 动画演示（内存真相）：**
> 
> 1. **堆内存（建筑区）** 里出现了一个房子，门牌号上写着 `"Hello"`。
>     
> 2. 指针 `s` 手里拉着电线，连接到了 `"Hello"` 的房子。
>     
> 3. 当你执行 `s + " World"` 时，Java **并没有**在原有房子后面贴几个砖块变成 `"Hello World"`。
>     
> 4. 而是**轰隆一声**，在旁边直接盖了一间全新的豪华大别墅，里面写着 `"Hello World"`！
>     
> 5. 电线 `s` “咔哒”一声，剪断了和原房子的连接，插到了新别墅上。
>     
> 6. 原来的 `"Hello"` 变成了一间没有人住的废弃荒宅（等待垃圾回收）。
>     

**关键难点拆解：**

`String` 的底层其实是一个用 `final` 修饰的字符数组（Java 9+ 变成了字节数组 `byte[]`）。`final` 意味着一旦出生，**字符数组的长度和内容就永远死封在石碑上，谁也改不了**。

### 🚨 深度难点单独讲：字符串常量池（String Constant Pool）

这是所有面试和实际开发中最容易踩坑的内存机制！

#### 两种创建字符串的方式，到底有什么区别？

Java

```
String str1 = "abc";               // 方式 A：直接双引号
String str2 = new String("abc");   // 方式 B：new 对象
```

> **🎬 动画演示（常量池 vs 堆）：**
> 
> **方式 A (`String str1 = "abc"`)：**
> 
> 1. Java 跑到堆内存里一个叫 **“字符串常量池”** 的专属VIP仓库门前。
>     
> 2. 探头往里看：“有 `"abc"` 吗？”
>     
> 3. **发现没有**：立即在常量池造一个 `"abc"`，把地址给 `str1`。
>     
> 4. 如果你紧接着写 `String str3 = "abc";`，Java 再去仓库看：“有了！” 于是直接把 `str3` 的电线也插到**同一个 `"abc"`** 上。
>     
> 5. **结果**：`str1 == str3` 返回 **`true`**（它们指向同一个房间）。
>     
> 
> **方式 B (`String str2 = new String("abc")`)：**
> 
> 6. `new` 关键字是个强迫症暴发户，它说：“我不管仓库有没有，我必须在普通堆内存里**再买一块地，盖个新房子**！”
>     
> 7. 即使常量池里有 `"abc"`，它也要在堆里复制一份新的。
>     
> 8. **结果**：`str1 == str2` 返回 **`false`**（地址根本不一样）。
>     

> 💡 **老师总结：**
> 
> - **`==`** 比较的是**内存地址**（是不是同一个房子）。
>     
> - **`equals()`** 比较的是**房子里的内容**（内容是不是都叫 "abc"）。
>     

### 2. 救星登场：`StringBuilder` 与 `StringBuffer`

既然 `String` 拼接时会频繁盖新房子、造废弃房，非常浪费内存，如果我们要在循环里拼成百上千个字符串，该怎么办？

这时就需要 **“可变字符序列”** 救场了！

Java

```
StringBuilder sb = new StringBuilder("Hello");
sb.append(" World"); // 真正地在原房子上扩建！
```

> **🎬 动画演示（StringBuilder 的扩容）：**
> 
> 1. `StringBuilder` 内部有一个**可伸缩的皮筋小盒子**，默认容量是 $16$。
>     
> 2. 你往里面塞字符串，它直接在盒子内部修改，**不产生任何新对象**。
>     
> 3. 如果盒子装满了，它会自动把皮筋拉长（把容量扩大为原来的 $2 \times N + 2$ 倍），继续往里装。
>     

#### StringBuilder vs StringBuffer（PK 环节）

|**工具**|**线程安全性**|**性能速度**|**使用场景**|
|---|---|---|---|
|**`StringBuilder`**|线程不安全（没有锁）|🚀 极快|单线程拼接（日常开发 **90%** 用它）|
|**`StringBuffer`**|线程安全（加了 `synchronized` 防弹锁）|🐢 稍慢|多线程共享拼接|
