📽**动画场景引入**

欢迎来到“Java内存城”最豪华的洗浴中心！这里的核心设施是一个**超级VIP储物柜系统（HashMap）**。

在这个储物柜里，存东西必须是一对一对的：一把**钥匙（Key）**对应一个**物品（Value）**。

当你拿着钥匙 "A01" 和你的劳力士手表（Value）来寄存时，前台有一个非常聪明的“算命先生”（哈希函数）。他看了一眼你的钥匙 "A01"，掐指一算（计算 Hash 值），大喊一声：“把劳力士放到第 5 号柜子！”你瞬间就能把东西放进去。

取东西时也一样，算命先生一算，直接告诉你去 5 号柜拿，**速度快如闪电，根本不用挨个柜子找！**

但是，算命先生偶尔也会失误，比如看了钥匙 "B02"，他也算出了“第 5 号柜子”！这就是著名的“哈希冲突”**。 怎么办呢？5 号柜子里已经有劳力士了！ 神奇的事情发生了：5 号柜子的底部突然掉下了一根**长绳子（链表 LinkedList）**，后来的 "B02" 的物品就顺着绳子绑在劳力士下面。 如果绑的物品越来越多，绳子越来越长（超过8个），找东西太慢了怎么办？ “砰！”的一声巨响，长绳子瞬间变形成了一棵**高科技的机器树（红黑树 Red-Black Tree）！在这棵树上找东西，哪怕挂了成千上万件，也能一秒钟找到！

📖**核心概念**

HashMap 是用来存储 **键值对（Key-Value）** 的数据结构。

- **到底是什么**：它就像一个字典，通过目录（Key）能瞬间找到对应的一页（Value）。
    
- **解决什么问题**：解决了“根据特定的名字/编号，瞬间查找对应数据”的问题。它的查找和插入速度极快，几乎是瞬间完成（时间复杂度 $O(1)$）。
    

🧠**底层原理（JDK 8及以后）**

HashMap 的肚子里，其实是一个 **“数组 + 链表 + 红黑树”** 的超级缝合怪！

1. **主干是数组**：就像一排连续的柜子，默认有 16 个。
    
2. **算命定位（Hash）**：存入 `(Key, Value)` 时，底层会调用 Key 的 `hashCode()` 方法算出一串数字，经过精密计算得出它该放在数组的哪个位置（下标）。
    
3. **链表化**：如果不同的 Key 算出了同一个位置，它们就会在这个位置手拉手形成一条**链表**。
    
4. **树化（高频考点）**：当某条链表上的元素数量 **大于 8**，并且整个数组的长度 **大于等于 64** 时，这条链表就会变异成 **红黑树**。红黑树是一种极其高效的树形结构，能把慢吞吞的链表查询速度提升几十倍！
    
5. **魔法扩容（负载因子）**：储物柜不能塞得满满当当才加柜子，那样发生“哈希冲突”的概率太高了。HashMap 设了一个报警器叫**负载因子（默认 0.75）**。当 16 个柜子用了 75%（也就是 12 个）时，系统会自动花大价钱，把柜子数量翻倍扩容到 32 个，并把所有物品重新算命换位置（这叫 Rehash，很耗性能）。
    

💻**基础语法&常用API**

来看看怎么操作这个高级储物柜：

Java

```
import java.util.HashMap;
import java.util.Map;

public class HashMapTheater {
    public static void main(String[] args) {
        // 1. 买一个储物柜，规定钥匙(Key)是String，物品(Value)是Integer
        HashMap<String, Integer> map = new HashMap<>();
        
        // 2. 存东西 (put) - 钥匙不能重复，物品可以重复
        map.put("张三", 100); // 张三考了100分
        map.put("李四", 80);
        map.put("张三", 95);  // ⚠️注意：钥匙重复了！原来的100分会被无情覆盖掉！
        
        // 3. 取东西 (get)
        Integer score = map.get("张三"); // 算命先生直接告诉你：张三是 95 分
        
        // 4. 看看有没有这把钥匙 (containsKey)
        boolean hasLi = map.containsKey("李四"); // true
        
        // 5. 丢掉东西 (remove)
        map.remove("李四");
        
        // 6. 核心遍历方式（把柜子里所有的键值对拿出来）
        // entrySet() 会把每一个 (Key-Value) 打包成一个小盲盒(Entry)
        for (Map.Entry<String, Integer> entry : map.entrySet()) {
            System.out.println("钥匙：" + entry.getKey() + "，物品：" + entry.getValue());
        }
    }
}
```

⚠️**高频坑&易错点**

**致命大坑：用自定义的类当 Key，却忘记重写 `hashCode()` 和 `equals()`！**

- **坑在哪里**：你写了一个 `Student` 类，`new` 了一个叫小明的学生当钥匙存进 HashMap。过了一会儿，你又 `new` 了一个名字也叫小明的学生，去 HashMap 里面取数据，结果返回了 `null`！
    
- **为什么错**：因为 HashMap 的“算命先生”默认只看**内存地址**！你 `new` 了两次，就算名字一样，内存地址也不同，算命先生会认为这是两把完全不同的钥匙，指路指到了空的柜子！
    
- **正确姿势**：如果要把自己写的类当成 HashMap 的 Key，**必须**在类里重写 `hashCode()` 和 `equals()` 方法，告诉算命先生：“只要名字一样，你就算出同一个密码！”（现阶段可以直接用IDEA快捷键生成这两个方法）。
    

✅**课堂小结**

- **本质**：存储 **键值对 (Key-Value)** 的集合，Key 唯一，Value 可重复。
    
- **底层**：**数组 + 链表 + 红黑树**（链表 > 8 且数组 >= 64 变红黑树）。
    
- **扩容**：默认大小 16，负载因子 **0.75**，达到阈值扩容为原来的 **2倍**。
    
- **核心动作**：算命定位（Hash计算），极速查找。
