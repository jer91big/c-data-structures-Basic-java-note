## 💡 为什么叫“匿名内部类”？

- **内部类**：因为它写在其他类的内部（比如写在某个方法里面）。
    
- **匿名**：因为它**没有显式的名字**。你不需要像平时那样写 `public class MyClass`。
    

### 🎭 画面感演示：从“老实人”到“刺客”

假设我们要给按钮绑定一个点击事件（或者创建一个线程）。

#### 1. 老实人的做法（定义正规类）

你可以想象成做一道菜前，先专门买个碗，给碗起个名字叫 `MyDish`，把菜装进去，用完一次就把碗扔了。

- **第一步**：写一个文件 `MyClickListener.java` 实现接口。
    
- **第二步**：在大脑/代码里给它起个名字叫 `MyClickListener`。
    
- **第三步**：在主代码里 `new MyClickListener()`。
    

> **缺点**：为了用一次，我得额外写一个类文件，还要苦思冥想给它起名字，极度繁琐！

#### 2. 匿名内部类的做法（刺客做法：见缝插针）

我不买碗了，也不给类起名字了。**我直接在需要用到的地方，当场把这个类定义出来，当场 `new` 使用！** 用完即走，不留痕迹。

## 语法拆解：它到底长啥样？

匿名内部类最核心的语法格式只有这一块：

Java

```
new 父类构造器/接口名() {
    // 1. 在这里实现/重写方法
    // 2. 甚至可以定义自己的属性
}; // 注意：末尾有一个分号！
```

### 🛠️ 代码对比（最直观）

假设我们有一个接口：

Java

```
public interface Swimable {
    void swim(); // 游泳能力
}
```

#### 传统写法（需要专门写个子类）：

Java

```
// 必须先写一个具体的子类
class Frog implements Swimable {
    @Override
    public void swim() {
        System.out.println("青蛙用蛙泳在水里游...");
    }
}

// 使用时：
Swimable s = new Frog();
s.swim();
```

#### 匿名内部类写法（一行搞定，不写子类）：

Java

```
// 直接 new 接口，在大括号里现场写实现！
Swimable s = new Swimable() {
    @Override
    public void swim() {
        System.out.println("匿名大侠在水里狗刨...");
    }
};

s.swim(); // 调用方法
```

> ⚠️ **新手最容易晕的地方**：`new Swimable()` 是不是在实例化接口？ **绝对不是！** 接口不能被 `new`。这里的本质是：**Java 在后台偷偷创建了一个“不知道叫啥名字的子类”，这个子类实现了 `Swimable` 接口，然后 `new` 出了这个子类的对象！**

## 🛠️ 2 个高频实战场景

在以后的开发中，你会频繁在以下地方遇到它：

### 场景一：多线程（`Thread` 和 `Runnable`）

在开启一个新线程时，我们经常需要传一个任务。

Java

```
// 传统做法：写一个 MyTask 实现 Runnable
// 匿名内部类做法：
Thread t = new Thread(new Runnable() {
    @Override
    public void run() {
        System.out.println("子线程正在悄悄干活...");
    }
});
t.start();
```

### 场景二：数组/集合排序（`Comparator` 比较器）

比如你想给一堆学生按成绩从大到小排序：

Java

```
List<Student> list = getStudents();

// 现场定义排序规则，用完就废弃
Collections.sort(list, new Comparator<Student>() {
    @Override
    public int compare(Student o1, Student o2) {
        return o2.getScore() - o1.getScore(); // 降序
    }
});
```

## ⚡ 匿名内部类的“三大铁律”

1. **只能用一次**：因为它没有名字，你无法在别的地方再次 `new` 它。它诞生即为了当前这一行代码服务。
    
2. **不能写构造方法**：因为构造方法的名字必须和类名一致，而它根本没有类名！
    
3. **访问局部变量的限制**：如果在匿名内部类里用到了外面方法的变量，那个变量必须是 `final`（或者隐式不可变的）。
    

## 🚀 进阶：它和 Java 8 的 Lambda 表达式是什么关系？

当你学会了匿名内部类，你会觉得大括号里写这么多代码还是有点冗长。 Java 8 推出了 **Lambda 表达式**，用来进一步简化**只有一个抽象方法的接口**的匿名内部类！

- **匿名内部类：**
    
    Java
    
    ```
    new Thread(new Runnable() {
        @Override
        public void run() {
            System.out.println("Hello!");
        }
    }).start();
    ```
    
- **进化为 Lambda 表达式（极致精简）：**
    
    Java
    
    ```
    new Thread(() -> System.out.println("Hello!")).start();
    ```
    

> 💡 **总结**：Lambda 表达式本质上就是匿名内部类的**语法糖**（极简版写法）。但前提是：你要先懂匿名内部类的逻辑，看 Lambda 才不会懵！
